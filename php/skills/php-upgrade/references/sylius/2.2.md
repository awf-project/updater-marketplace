# Upgrade from Sylius 2.1 to 2.2

- The application overrides checkout form constructors. [Checkout address modifiers](#checkout-address-modifiers)
- Deployment restricts usage telemetry. [Telemetry policy](#telemetry-policy)
- The exact target is 2.2.7 or newer and overrides payment workflow. [Payment retries after cancellation](#payment-retries-after-cancellation)

## Checkout address modifiers

For a subclass or service override of the shop checkout address `FormComponent`, forward the new final `$addressFormValuesModifiers` argument with the `sylius_shop.modifier.address_form_values` tagged iterator. Omitting it is deprecated in 2.2. Run address validation and submission with the same channel and customization. Assert that the modifier still applies and that expected address fields persist.

## Telemetry policy

2.2 enables telemetry by default. Set `SYLIUS_TELEMETRY_ENABLED=0` for environments requiring it and confirm the application sees the setting in the deployed runtime.

## Payment retries after cancellation

Allow `request_payment` from `authorized` and `partially_authorized` in addition to `cart`. Align custom `OrderPaymentStateResolver` logic for remaining `cart` or `new` payments. In a test gateway, cancel an authorization and verify the order returns to `awaiting_payment`, accepts the retry, and records effects only once.
