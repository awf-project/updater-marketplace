# Upgrade from Sylius 1.14 to 2.0

- The app uses Sylius plugins, Plus modules, or Standard recipes. [Composer and deployment order](#composer-and-deployment-order)
- The app uses Payum, Winzou, or custom checkout state transitions. [Payment gateways and workflow](#payment-gateways-and-workflow)
- Shop or admin APIs or custom API Platform extensions are in use. [API and firewalls](#api-and-firewalls)
- The app overrides legacy Twig templates, events, or assets. [Storefront and admin templates](#storefront-and-admin-templates)

## Composer and deployment order

Resolve actual PHP, Symfony, Doctrine, and API Platform constraints with the installed plugins. Compare the target Sylius Standard configuration and asset flow against the files the project customized. Rehearse Doctrine migrations with representative order/payment data. Check that workers and rollback procedures match the resulting schema before proposing a deployment order.

## Payment gateways and workflow

Move `sylius_payum.resources.gateway_config.classes.model` to `sylius_payment.resources.gateway_config.classes.model` and import `@SyliusPayumBundle/Resources/config/app/config.yaml`. Validate an existing gateway record and a checkout using a test gateway. If keeping Winzou, require `winzou/state-machine` and `winzou/state-machine-bundle` explicitly.

When switching to Symfony Workflow, compare transition guards, resulting order, payment and shipment states, and callbacks with persistent side effects. Use a stored order in an intermediate state as well as a new checkout, and verify that a failed or retried action does not duplicate effects.

## API and firewalls

Rename `new_api_admin_user` and `new_api_shop_user` to `api_admin` and `api_shop`. Preserve matcher order and align corresponding `security.user_checker.chain.*` service references. Test shop and admin credentials against both namespaces, including denials. For custom API Platform extensions, follow the steps between the actual lockfile versions. A project moving from 3.4 to 4.0 already uses the new metadata model. [API Platform release index](../api-platform/index.md)

## Storefront and admin templates

Map each customization to the real hook in the corresponding target template and verify it renders once in the intended position. Rebuild the asset entry points actually used by those pages. Exercise both storefront and admin views wherever the app overrides the same component in both.
