# Upgrade from API Platform 4.2 to 4.3

- Operations use ExactFilter or PartialSearchFilter from parameter metadata. [Doctrine filters](#doctrine-filters)
- An entity is read-only or output is paired with itemUriTemplate. [Routes and JSON-LD metadata](#routes-and-json-ld-metadata)
- An operation's security expression does not use object. [Authorization ordering](#authorization-ordering)

## Doctrine filters

A parameter-based `ExactFilter`, `PartialSearchFilter`, `IriFilter`, or `UuidFilter` can throw `InvalidArgumentException` without a property. For example, map `q` to `new QueryParameter(property: 'name', filter: new ExactFilter())` or use the `:property` placeholder when exposing several properties. Verify the exposed parameter names in OpenAPI and compare results for every intended property, including invalid and omitted values.

## Routes and JSON-LD metadata

Check that expected routes exist because default PUT and PATCH are dropped for Doctrine read-only entities. For operations combining `output` and `itemUriTemplate`, verify the returned JSON-LD `@type` with existing consumers. Hydra consumers should test resolution of `#ShortName` class IDs and `rdfs:subClassOf` metadata.

## Authorization ordering

Evaluate behavior for explicitly allowed and denied requests. Expressions without `object` may block a request before invoking its provider. Remove assumptions that provider side effects occur on denial and verify the same status and response contract.
