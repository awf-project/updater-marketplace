# Upgrade from API Platform 3.4 to 4.0

- Configuration contains keep_legacy_inflector or event_listeners_backward_compatibility_layer. [Removed options and listener pipeline](#removed-options-and-listener-pipeline)
- Clients parse Hydra fields or derive resource names. [JSON-LD consumers](#json-ld-consumers)
- Custom catches or normalizers reference Symfony ValidationException. [Validation errors](#validation-errors)

## Removed options and listener pipeline

Complete the [3.4 bridge](3.4.md#40-compatibility-switches) first where possible. Remove the retired `keep_legacy_inflector`, `event_listeners_backward_compatibility_layer`, and `rfc_7807_compliant_errors` flags after porting consumers. If clients used an implicitly registered PUT, declare `new Put()` in the resource’s operation list alongside its other public operations. 4.0 drops PUT from the default set. `use_symfony_listeners` defaults to false, so select the Symfony listener pipeline explicitly for operations depending on it. Verify that the intended controller, listener, or processor runs once and that HTTP response generation still follows the app's contract.

## JSON-LD consumers

Review `serializer.hydra_prefix`, which defaults to false. If clients need prefixed Hydra keys, pin the previous setting and test both collection and error responses with the actual JSON-LD media type. Compare route and IRI output separately if removing legacy inflection changed names.

## Validation errors

Move version-specific references from `ApiPlatform\Symfony\Validator\Exception\ValidationException` to the corresponding `ApiPlatform\Validator\Exception\ValidationException`. Send invalid input through each affected operation and assert status, media type, payload, and field violations. [Upgrade guide](https://api-platform.com/docs/core/upgrade-guide/)
