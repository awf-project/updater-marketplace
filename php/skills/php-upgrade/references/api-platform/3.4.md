# Upgrade from API Platform 3.3 to 3.4

- The project is considering split packages or also integrates Sylius. [Composer package split](#composer-package-split)
- Custom listeners or controllers and legacy inflection are in use. [4.0 compatibility switches](#40-compatibility-switches)
- Clients omit properties in PUT updates. [Partial PUT behavior](#partial-put-behavior)

## Composer package split

List the installed `api-platform/core` or split packages and their integration bridges from the lockfile. For a split on Symfony, resolve `api-platform/symfony` and only the required bridges, such as `api-platform/doctrine-orm`. If Sylius constrains the dependency, resolve its API bundle with that graph. Confirm bundle loading and resource discovery before changing endpoint behavior.

## 4.0 compatibility switches

Move listeners/controllers relying on Symfony events to explicit `use_symfony_listeners` where required. For a custom inflection rule, implement `ApiPlatform\Metadata\InflectorInterface` and select its service with `api_platform.inflector`. Compare irregular route names, JSON-LD/Hydra fields, and a request that reaches custom listener logic. [Upgrade guide](https://api-platform.com/docs/core/upgrade-guide/)

## Partial PUT behavior

On 3.4, `defaults.extra_properties.standard_put` becomes true. Compare a write that omits a nullable property against the existing API contract and pin desired behavior where needed. Cover both update and creation if the same operation previously supported both.
