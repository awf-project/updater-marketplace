# Upgrade from API Platform 4.4 to 5.0

- Clients consume JSON:API resource IDs, relationship links, or self links. [JSON API identifiers](#json-api-identifiers)
- The project wires DeserializeProvider manually or extends PropertyAwareFilterInterface. [Service decorators and filters](#service-decorators-and-filters)
- Operations disable query validation or tests use API Platform helpers. [Parameter validation and test package](#parameter-validation-and-test-package)

## JSON API identifiers

The `use_iri_as_id` default becomes false. Set `api_platform.jsonapi.use_iri_as_id` to true where clients still require IRIs, or migrate consumers with the server. Exercise a real resource, its related data, and self-link traversal. Check resource IDs and links independently.

## Service decorators and filters

Remove the fourth `TranslatorInterface` argument from custom `DeserializeProvider` wiring and move any positional `DenormalizationViolationFactoryInterface` from fifth to fourth. Exercise an invalid payload to confirm the correct deserialization error reaches the existing normalizer. Supply `getProperties()` or use `PropertyAwareFilterTrait` where required. Test a configured property and an unsupported one through the same operation.

## Parameter validation and test package

Remove `validator.query_parameter_validation` because validation is always enabled. Test absent and invalid values on operations that previously disabled it. If those clients depended on permissive behavior, adjust the contract or data before rollout.

For JSON:API error consumers, parse `errors[].status` as a string. When targeting 5.0.4, include an invalid backed enum in the HTTP tests because that patch restores the 422 response. [5.0.4 changes](https://api-platform.com/docs/changelog/#v504)

Move used helpers to the `api-platform/test` dev package and migrate affected imports to `ApiPlatform\Test`. Run HTTP assertions against the affected endpoints. Existing legacy Doctrine filters can be migrated independently when supported. [Upgrade guide](https://api-platform.com/docs/core/upgrade-guide/)
