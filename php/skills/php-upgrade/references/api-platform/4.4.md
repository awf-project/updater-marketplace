# Upgrade from API Platform 4.3 to 4.4

- When replacing a 4.4 beta or updating error-contract tests, use the stable 4.4.0 semantics. A plain type mismatch on a constrained field yields 400, while an invalid backed-enum value yields 422. Send both payloads through the deployed serializer. The constraint-aware change was deferred to 5.0.
- On Symfony, resolve `^7.4 || ^8.0` before raising API Platform to 4.4. If using `api-platform/doctrine-orm`, the ORM constraint is `^2.17 || ^3.3`. With DoctrineBundle, resolve `^2.11.1 || ^3.1`. On ORM 3, 2.11.0 passes a removed argument to the mapping driver. If the app uses `fetch_partial`, exercise a partial query after leaving ORM 3.0.0–3.2.3, which lacked the `PARTIAL` grammar.
- JSON:API consumers → set `api_platform.jsonapi.use_iri_as_id: true` if clients need IRIs in `data.id` through 5.0. Assert IDs and self links.
- `#[ApiFilter]` or old Symfony `AccessDeniedException` → inspect any `api:upgrade-filter` diff and use `ApiPlatform\Metadata\Exception\AccessDeniedException` for custom denial handling.
