# Upgrade from Symfony 7.3 to 7.4

- Symfony loads XML routes or services, or fluent configuration builders. [Configuration formats](#configuration-formats)
- Bootstrap code invokes Console Application add. [Console registration](#console-registration)
- The next step crosses into Symfony 8. [Deprecation checkpoint](#deprecation-checkpoint)

## Configuration formats

Inventory application config and imports from bundles or Flex recipes. Convert routes and configuration to supported formats while still on 7.4 where possible. Compare environment-specific imports, resource paths, route priority, and container wiring.

For fluent semantic PHP config deprecated on this bridge, return the extension configuration as a PHP array, use `$container->extension()` in a PHP config closure, or port it to YAML. Validate the compiled configuration in the environment that actually imports it.

## Console registration

Use `addCommand()` and check callers that read the returned command or attach aliases. Validate command registration with the same bootstrap as schedulers and workers.

## Deprecation checkpoint

Run applicable deprecation checks on 7.4 with the actual bundle set. Trace each failure to application code, a recipe, or a dependency before raising constraints. If a needed integration cannot resolve on 8.x, record its blocker. 7.4 LTS can serve as the deployment checkpoint. [Symfony 7.4 requirements](https://symfony.com/releases/7.4)
